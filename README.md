# Content Pulse Studio

Отбор по карточкам для своих съёмок — без Яндекс Диска. Кадры, превью и отбор лежат
в закрытом бакете Object Storage (Yandex Cloud), страница — на GitHub Pages.

Отдельная версия от Content Pulse 2.0 (репозиторий `content-pulse`, витрина поверх
Диска для команды SK). Общий движок карточек — Cardboard (`content-pulse-cardboard`).

## Как работает

1. **Владелец** (вход по ключу) создаёт проект, загружает съёмку, раскладывает отбор
   по карточкам.
2. У проекта две ссылки, обе бессрочные:
   - **редактирование** — править отбор, подписывать карточки, согласовывать, скачивать;
   - **скачивание** — смотреть текущий отбор и скачать всё или отбор (для ретушёров).
   Владелец может сменить любую из них — старая перестанет работать, вторая останется.
3. Клиент правит отбор по первой ссылке, ретушёр по второй всегда видит и качает
   то, что сейчас в отборе: на каждую карточку — папка с её подписью.

Кто открыл ссылку, при первом входе называет себя — в журнал пишется, кто, что и когда.

## Скачивание

Скачать можно отбор (кадры в карточках и доп. контенте) или все кадры съёмки. Две галки:

- **Папками** — по папке на карточку с её названием; без галки — одной кучей;
- **Переименовать файлы** — `<название карточки>_<позиция в карточке>.jpg`; без галки — исходные имена.

Карточка без названия — «Карточка N». Совпадающие имена получают « (2)». Перед скачиванием
страница сверяется с облаком — архив всегда по текущему отбору.

## Устройство

| Путь | Что |
|---|---|
| `index.html` | Cardboard из Content Pulse 2.0 (вёрстка карточек, шаблоны, галерея, PDF) без модулей Диска |
| `studio.js` | облачная часть: вход, съёмки, загрузка (превью и CRC в браузере), сохранение со склейкой правок, согласование, ссылки, журнал, скачивание, просмотр для ретушёра |
| `studio.css` | стили облачной части |
| `proxy/index.js` | прослойка (Yandex Cloud Function): доступ, проекты, ссылки, отбор, загрузка, архив |
| `tools/bucket-setup.js` | настройка бакета: закрытый, жизненный цикл, CORS |
| `tools/deploy.js` | выкладка прослойки в Cloud Functions |
| `tools/smoke.js` | проверка живой прослойки на настоящем облаке |
| `tests/proxy.test.js` | прослойка на подменном хранилище (`tests/fake-s3.js`) |
| `tests/e2e.test.js` | страница в настоящем Chrome: владелец, клиент, конфликт правок, ретушёр, все варианты скачивания |

Бакет:

```
projects/<pid>/meta.json    имя, дата, токены двух ссылок
projects/<pid>/state.json   отбор: кадры (имя, размер, CRC), карточки, подписи, согласования, журнал; rev
projects/<pid>/o/<fid>      оригиналы
projects/<pid>/p/<fid>.jpg  превью (делает браузер при загрузке)
shares/<token>.json         {pid, mode}
exports/<rand>.zip          архивы скачивания — правило бакета удаляет через 3 дня
```

Проекты сами не удаляются — только кнопкой владельца.

Одновременные правки: страница сохраняет отбор с номером ревизии, с которой начала;
если кто-то успел раньше — прослойка отвечает 409 с текущим отбором, страница склеивает
правки и сохраняет снова.

Архив собирается в облаке (трафик внутри облака бесплатный) многочастной загрузкой —
один ZIP любого размера (ZIP64), русские имена папок читаются в macOS, Windows и unzip.

## Переменные окружения функции

`S3_KEY_ID`, `S3_SECRET`, `S3_BUCKET` — статический ключ сервисного аккаунта и бакет;
`OWNER_KEY` — ключ владельца (не короче 12 знаков); `ALLOWED_ORIGINS` — адрес страницы.

## Проверка

```bash
node tests/proxy.test.js                 # прослойка, 41 проверка
node tests/e2e.test.js                   # страница в Chrome, 31 проверка (нужен playwright)
node tools/smoke.js <studio-keys> <адрес функции>   # живое облако
```

## Выкладка

Страница — GitHub Pages из ветки main. Прослойка — `node tools/deploy.js <studio-keys>`
(ключи — в папке studio-keys на Маке, не в репозитории).
